# storeboard — 매장 마케팅·매출 리포트 슬라이드

주간/월간/작년 매출표, 네이버 플레이스 유입 리포트, 광고 리포트(네이버·구글·메타…)
**캡처를 넣으면 보고용 16:9 슬라이드**로 만들어 줍니다.

```bash
storeboard report shots/ --period 2026-W33 --brand 불도저파크
```

```
out/직영점-주간-마케팅매출-리포트-2026-W33/
├── slides/01_cover.png … 09_appendix.png   ← PPT·메신저에 그대로
├── deck.pdf        ← 보고 자리에서 띄우는 파일 (슬라이드당 한 쪽)
├── deck.html       ← 브라우저 미리보기 (파일 하나로 완결)
├── report.json     ← 판독된 원본 데이터. 고쳐서 다시 빌드할 수 있습니다
└── summary.txt     ← 단톡방에 붙여 넣는 텍스트 요약
```

## 슬라이드 구성 — 보고 자리에서 나오는 질문 순서

한 장 = 한 질문. 데이터가 없는 장은 아예 만들지 않습니다(빈 칸을 보여주지 않습니다).

| # | 슬라이드 | 답하는 질문 | 들어가는 것 |
|---|---|---|---|
| 1 | 표지 | 누구의 · 언제 실적인가 | 브랜드 · 기간 · 대상 매장 |
| 2 | **한눈에** | 이번 기간 결론은 | 매출(대표 숫자) · 전년비 · 객단가 · 광고비 · 광고비율 · ROAS · 핵심 코멘트 4개 · 목표 달성률 |
| 3 | 매출 추이 | 흐름이 좋아지고 있나 | 최근 8기간 막대 + 전년 동기 겹쳐보기 + 기간별 표 |
| 4 | 매장별 | 어디가 끌고 어디가 빠졌나 | 매장별 매출 막대 · 전기 대비 증감(발산형) · 매장 상세표 |
| 5 | 채널 효율 | 광고비를 어디에 썼고 뭐가 남았나 | 광고비 배분 · 채널별 ROAS(목표선) · CTR/CPC/CVR/CPA/ROAS 표 |
| 6 | 광고 퍼널 | 어느 단계에서 새나 | 노출→클릭→전환 · 채널별 CPA · 구간별 1위/최하위 |
| 7 | 네이버 유입 | 찾아온 사람이 행동했나 | 조회수 · 행동 전환율 · 유입 경로 구성 · 상위 검색어 |
| 8 | 인사이트·액션 | 다음 기간에 뭘 할 건가 | 코멘트 정리 · 담당·기한이 붙은 액션 |
| 9 | 부록 | 근거는 어디에 | 원본 캡처 · 읽지 못한 항목 · 메모 |

### 왜 이 순서인가

- **결론부터.** 2번 슬라이드만 봐도 보고가 끝나야 합니다. 나머지는 근거입니다.
- **매출 → 매장 → 채널 → 유입.** 큰 숫자에서 작은 숫자로 좁혀 들어갑니다.
  반대로 가면 "그래서 매출은 어떻게 됐는데?"가 마지막에 나옵니다.
- **마지막은 항상 액션.** 담당과 기한이 없는 인사이트는 다음 주에 그대로 다시 나옵니다.

## 지표 정의 — 보고 자리에서 말이 갈리는 것들

| 지표 | 계산 | 왜 이렇게 |
|---|---|---|
| **ROAS (실매출 기준)** | 전체 매출 ÷ 전체 광고비 | 채널 리포트 합보다 보수적입니다. 채널들은 같은 주문을 서로 자기 성과로 잡습니다 |
| ROAS (채널 리포트 기준) | 채널이 집계한 전환매출 ÷ 광고비 | 채널 간 상대 비교용. 절대값으로 믿지 않습니다 |
| **매출 대비 광고비** | 광고비 ÷ 매출 × 100 | 외식업에서 제일 먼저 보는 방어선. 목표 상한을 넘으면 빨간 코멘트가 붙습니다 |
| 객단가 | 매출 ÷ 방문 고객수 (없으면 결제 건수) | 매출이 빠졌을 때 손님이 준 건지 덜 쓴 건지 가릅니다 |
| CPA | 광고비 ÷ 전환수 | 채널마다 전환 정의가 달라 채널 간 비교는 참고용입니다 |
| **행동 전환율** | (예약 + 전화 + 길찾기) ÷ 플레이스 조회수 | 유입이 실제 방문 의사로 이어졌는지. 조회수만 보면 착시가 생깁니다 |
| 전주 대비(WoW) | 직전 주 대비 | |
| 전년 동기(YoY) | 주간은 **364일 전 같은 요일** | 주차 번호를 그냥 빼면 요일 구성이 어긋나 비교가 망가집니다 |

비교 대상 데이터가 없으면 **0%가 아니라 "—"** 로 둡니다. 없는 걸 0으로 찍으면
보고 자리에서 잘못된 결론이 나옵니다.

## 세 가지 사용법

### 1. 캡처를 넣는다 (`ANTHROPIC_API_KEY` 필요)

```bash
storeboard report shots/ --period 2026-W33 --brand 불도저파크
```

캡처 한 장씩 읽어 `report.json` 으로 합친 뒤 슬라이드까지 만듭니다.
판독만 하려면 `storeboard extract shots/ -o report.json`.

### 2. 손으로 채운다 (키 없이)

```bash
storeboard template -o report.json --period 2026-W33 --stores 강남점,홍대점,판교점
# report.json 을 채운 뒤
storeboard build report.json
```

### 3. 먼저 모양만 본다

```bash
storeboard sample        # 가짜 데이터로 덱 한 부. 키도 캡처도 필요 없습니다
```

## 캡처 준비 요령

판독 정확도는 캡처 품질이 거의 다 결정합니다.

- **표 머리글까지 포함해서** 찍습니다. `(단위: 천원)` 이 잘리면 금액이 1000배 틀립니다.
- **기간이 보이게** 찍습니다. 안 보이면 `--period` 로 준 값을 씁니다.
- 화면을 축소해서 표 전체를 한 장에 담는 편이, 잘라서 여러 장 찍는 것보다 낫습니다.
- 파일 이름에 종류를 넣으면 판독이 안정적입니다.

| 파일명 예시 | 인식 |
|---|---|
| `주간매출_0812.png`, `POS_정산.png` | 매출표 |
| `네이버플레이스_유입.png`, `naver_place.png` | 유입 리포트 |
| `메타광고.png`, `google_ads.png`, `네이버광고.png` | 광고 리포트 |

**읽지 못한 값은 지어내지 않습니다.** 흐리거나 잘린 항목은 비워 두고
`report.json` 의 `warnings` 와 부록 슬라이드에 "확인 필요"로 올립니다.
그 값들만 손으로 채우고 다시 `build` 하면 됩니다.

## report.json

```jsonc
{
  "title": "직영점 주간 마케팅·매출 리포트",
  "brand": "불도저파크",
  "period": "2026-W33",              // 주간 2026-W33 / 월간 2026-08 / 연간 2026
  "stores": ["강남점", "홍대점"],      // 비워두면 데이터에서 자동으로 뽑습니다
  "goal": { "revenue": 110000000, "roas": 4.0, "ad_ratio": 12.0 },

  "sales": [                          // 매장 × 기간. 전년 자료도 같은 배열에 넣습니다
    { "store": "강남점", "period": "2026-W33",
      "revenue": 48200000, "orders": 1420, "customers": 3266 }
  ],
  "ads": [                            // 채널 × 기간
    { "channel": "naver_sa", "period": "2026-W33", "store": "전체",
      "spend": 3800000, "impressions": 412000, "clicks": 12460,
      "conversions": 486, "revenue": 21900000 }
  ],
  "traffic": [                        // 네이버 플레이스 유입
    { "store": "강남점", "period": "2026-W33", "views": 18900,
      "inflow": { "search": 8700, "map": 3900, "ad": 3400, "blog": 1800, "direct": 1100 },
      "keywords": [{ "term": "강남 고깃집", "count": 3119 }],
      "saves": 580, "calls": 320, "reservations": 490,
      "directions": 900, "reviews": 76, "review_score": 4.6 }
  ],
  "captures": ["shots/주간매출.png"],  // 부록 슬라이드에 썸네일로 붙습니다
  "warnings": [],
  "notes": ""
}
```

- 금액은 **원 단위 정수**. `"1,234,000"`, `"340만"`, `"1.2억"` 같은 문자열도 읽습니다.
- 모르는 값은 `0` 으로 두면 지표에서 빠집니다(0으로 계산되지 않습니다).
- 채널·유입경로 키 목록: `storeboard channels`
- 합계 행만 있는 매출표는 `store` 를 `"전체"` 로 둡니다. 매장별 행과 섞여 있어도
  합계는 매장별 행에서만 계산하니 이중 계산되지 않습니다.

## 자주 쓰는 옵션

| 옵션 | 기본 | 설명 |
|---|---|---|
| `--period` | 데이터에서 추정 | 기준 기간. 캡처에 기간이 없을 때도 이 값을 씁니다 |
| `--history` | 8 | 추이 슬라이드에 넣을 기간 수 |
| `--format` | `png,pdf,html` | 필요한 것만 골라 뽑습니다 |
| `--scale` | 1 | PNG 배율. `2` 면 3840×2160 |
| `--offline` | 꺼짐 | Claude 를 부르지 않고 규칙 기반 코멘트만 씁니다 |
| `--clean` | 꺼짐 | 결과 폴더를 비우고 시작 |
| `-o/--out` | `out/<제목-기간>` | 결과 폴더 |

```bash
# 월요일 오전

# deck.pdf 를 회의에 띄우고, summary.txt 를 단톡방에 붙입니다
```

## 문제 해결

| 증상 | 원인 · 조치 |
|---|---|
| `기준 기간을 알 수 없습니다` | `report.json` 의 `period` 를 채우거나 `--period 2026-W33` |
| 금액이 1000배 큼/작음 | 캡처의 `(단위: 천원)` 머리글이 잘렸습니다. `report.json` 에서 수정 |
| 매장 비교 슬라이드가 없음 | 매장별로 나뉜 매출이 2개 이상 있어야 만듭니다 |
| PNG·PDF 가 안 나옴 | `python -m storeboard doctor` → 크로미움 설치 안내를 따르세요 |
| 한글이 시스템 서체로 나옴 | `python scripts/fetch_fonts.py` (없어도 렌더링은 됩니다) |
| 코멘트가 밋밋함 | `ANTHROPIC_API_KEY` 를 넣으면 Claude 가 같은 숫자로 문장을 다듬습니다 |

## 구조

```
storeboard/
├── cli.py          명령줄 (report / extract / build / sample / template / doctor)
├── pipeline.py     report.json → 결과 폴더까지의 전체 흐름
├── extract.py      캡처 이미지 → 구조화 데이터 (Claude 비전)
├── prompts.py      판독 프롬프트 + JSON 스키마
├── models.py       Report · SalesPoint · AdPoint · TrafficPoint
├── periods.py      기간 표기 한 가지 규칙 (WoW/YoY 계산의 근거)
├── metrics.py      파생 지표 (증감 · ROAS · CPA · 행동 전환율 …)
├── insights.py     코멘트·액션 (규칙 기반 + Claude)
├── charts.py       인라인 SVG 차트
├── deck.py         지표 → 슬라이드 구성
├── theme.py        색 토큰
└── render/
    ├── html.py     덱 → HTML
    ├── browser.py  HTML → PNG / PDF (크로미움)
    └── templates/  Jinja2 템플릿 + CSS
```

데이터 흐름은 한 방향입니다.

```
캡처 이미지 ─ extract ─→ report.json ─ metrics ─→ 지표
                              │                    ├─ insights ─→ 코멘트·액션
                              │                    ↓
                              └───────────────→ deck ─→ HTML ─→ PNG · PDF
```

`report.json` 이 유일한 원본입니다. 지표는 저장하지 않고 빌드할 때마다 다시 계산하므로,
원본을 고치면 슬라이드의 모든 숫자가 함께 바뀝니다.
